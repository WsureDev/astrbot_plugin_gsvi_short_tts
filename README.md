# astrbot_plugin_gsvi_short_tts

直接调用 GSVI HTTP 服务的 AstrBot 短文本 TTS 插件。群聊、私聊和 WebChat 各自设置音色、字数界限、触发概率，默认关闭。

## 安装与设置

在 AstrBot 插件页面通过仓库地址 `https://github.com/WsureDev/astrbot_plugin_gsvi_short_tts` 安装，也可以上传 ZIP，或将本目录放入 `AstrBot/data/plugins/astrbot_plugin_gsvi_short_tts/` 并重载。支持 AstrBot `>=4.28,<4.30`，复用其 aiohttp、Pydantic 等已有依赖。

在插件配置中填写 AstrBot 能访问的 GSVI 服务地址，并设置全局初始化预设。默认预设为“花火、100 字、100%”，但所有新渠道仍为关闭状态。

完全不依赖 AstrBot TTS Provider，不需要启用其语音合成开关。仅处理能确认来自 LLM 路径的输出：普通模型最终回复、Scheduler/cron Agent 结果、subagent 及 LLM 工具触发的异步消息。普通插件通知、普通指令回执和无法确认来源的消息保持原样。在平台事件的 `send/send_streaming` 和适配器的 `send_by_session` 入口转换实际要发送的消息。Live Mode 不在支持范围内。

本插件的开关和概率只管理本插件。若同时启用了 AstrBot 原生 TTS 或其他语音插件，它们仍有各自的触发规则；需要由本插件独立控制语音时，请关闭那些额外的自动转换。

## 音色下拉与刷新

1. 填写服务地址、版本和认证信息，保存配置。
2. 插件在后台请求 `/models/{version}`，稍后重新打开配置即可在“预设音色”中下拉选择。
3. 需要再次拉取时，勾选“刷新音色列表（执行一次）”并保存；开关自动复位，重新打开配置查看结果。

加载、重载和保存配置后会自动刷新，无需每次勾选。刷新不阻塞插件加载，最多等待 10 秒（配置的请求超时更短时使用更短值）。列表只更新运行时 Schema，插件目录中的 `_conf_schema.json` 不会被改写。

最近一次成功列表按服务地址和版本缓存在插件 KV 中。刷新失败时保留已有列表和当前选择，在音色字段提示中显示原因；首次加载失败且没有缓存时保留手动输入。服务端已移除的当前音色仍保留，并标注“当前选择，服务列表未列出”，不会自动改选其他音色。

此下拉框设置的是全局初始化预设。已通过 `/usetts` 保存的渠道音色继续独立生效，不随预设变化。

## 指令

| 指令 | 行为 |
| --- | --- |
| `/usetts 花火 80 50` | 当前渠道设置为花火、最多 80 字、50% 概率，并开启 |
| `/usetts on` | 已有配置则开启；没有配置则复制全局预设后开启 |
| `/usetts off` | 保留参数并关闭；没有配置则复制全局预设并保存为关闭 |
| `/usetts` | 查看状态、音色、字数、概率和配置来源，不写入设置 |
| `/usetts list` | 实时查询 GSVI 并列出当前版本全部音色，不改变渠道配置 |

字数必须为正整数，概率必须为 0–100 的整数。音色使用 `/models/{version}` 返回的角色键；包含空格时使用引号，例如 `/usetts "某个 角色" 80 50`。初始化时检查角色和情绪是否存在，错误不会覆盖现有配置。关闭已有配置不要求服务在线。

`/usetts list` 无需先开启或初始化渠道，始终查询服务端当前列表；查询失败时返回原因，不把旧缓存当作实时可用音色。列表回执为文字，不触发 LLM 或 TTS。

每个机器人实例下，每个群共用一份设置、每个私聊对象一份设置、每个 WebChat 用户会话一份设置。群设置不受 LLM 按群成员隔离会话的影响。设置复用 AstrBot 插件 KV 存储，重启保留；不同渠道独立写入。多实例需要共用 AstrBot 的持久化后端才能共享渠道设置，插件没有额外的全局配置缓存。

## 触发与发送

先确认消息来自 LLM 路径，再读取收件渠道的 TTS 配置。框架的模型结果结合请求所属任务和实际结果组件确认来源；Agent/工具执行期间的主动发送及派生后台任务通过独立 ContextVar 保留来源，cron/background_task 唤醒也按实际模型输出识别。不会根据文字内容、目的地、方法名，或者“事件曾调用过 LLM”来猜测来源。插件复用同一个 event 在其他任务中自行发信，不会因此自动归入模型输出。

普通 `/help` 等本地回执、插件自己的定时通知，以及没有 LLM 执行来源的裸 `Context.send_message` 不参与 TTS。插件通过指令真正调用框架 LLM，生成的模型回复仍属于 LLM 输出。第三方插件绕开框架自行调用模型再发送，若没有可确认的来源则原样保留，不擅自归类。

**必须整条消息的所有组件都是 `Plain`，才允许转语音。** 只要包含图片、文件、视频、提及、引用、转发、卡片或已有语音等任意非文字组件，就整条原样发送，不抽取概率、不调用 GSVI，不把图文消息中的文字单独转成语音。普通最终回复和异步主动发送使用相同限制。

对符合上述条件的最终响应或一次主动发送，按顺序拼接文字：去除首尾空白后按 Unicode 码点计数，中文、英文字母、标点和内部空白均计入。长度小于或等于界限且命中概率时生成一条 WAV 语音；0% 永不合成，100% 在长度满足时必定尝试。

成功后在发送副本中以一条语音替换纯文字正文，保留消息链元数据。模型响应、模型上下文、工具已发送文字记录和原生历史保存仍使用原文字；不修改 `LLMResponse.result_chain`。非纯文字、空文字、超长、未命中、HTTP 错误或合成失败均保留原回复，不截断文字。

执行顺序是：现有中间过程过滤 → AstrBot 原生发送判断与去重 → 实际发送入口 → 按目的地配置转换发送副本。TTS 不在 `on_llm_response` 中提前合成，不修改 Prompt、工具结果、fallback/retry 或模型调用次数，也不覆盖 `enable_streaming`、`enable_reasoning` 等请求选项。现有可恢复的 `ToolLoopAgentRunner.step()` 包装仅负责丢弃中间文本和工具状态、保留最终回复，仍覆盖 skills_like 重查询和工具直接结束；其中不再调用 TTS。

例如 `send_message_to_user` 已发送 A，最终 LLM 回复为 B：原生非流式流程判定 A==B 并去重时，仍只发送一次，也只对实际发送抽取一次 TTS 概率；A!=B 时，两次实际发送分别处理。本插件不补充语义去重或跨任务去重。原生流式流程有其自身规则，核查版本中同文案也可能保留两次发送，插件保持该行为。

模型的流式请求保留。呈现层按原生 `break` 等边界收集完整消息，确认整条纯文字后才尝试 TTS，不逐字或逐片段合成；未命中或合成失败时重放原始帧，图文保留原始组件。支持附件流的 WebChat 继续在原流中发送语音；其他平台的语音走其普通媒体发送口，避免文字流接口忽略语音。未开启渠道和 0% 渠道直接保留原来的流式呈现，不等待整段结束。

这些运行时包装不修改 AstrBot 源码，停用时恢复；与 `astrbot_plugin_llm_result_final_only` 可同时使用，不依赖其安装。其他包装相同方法的插件仍需一起验证。音频保留至实际平台发送结束后清理；流式附件保留到原生流消费结束，WebChat 会在此之前复制到附件目录。

主 Agent 与后台任务是两次独立回复。例如主 Agent 先发送“已经指派了任务”，后台稍后再发送天气结果；不会等待后台完成才放行主 Agent 的收尾。如果工具直接正常结束当前轮次、框架未生成正式最终响应，则保留这一个终止步骤的最后一条正文，不取更早步骤的内容，不合并过程文字。工具明确面向用户的 `tool_direct_result` 原样放行，图片和图文结果不会被当成工具状态丢弃。两个插件同时使用时，建议将“只发最终回复”也更新至 1.0.1 或以上。

### Scheduler、子 Agent 与异步主动发送

主动发送到达适配器 `send_by_session` 时先确认 LLM 来源，再按实际目标查询配置，不要求有入站事件，也不继承启动任务的群或私聊配置。`Context.send_message` 仅用于给新加载的适配器绑定发送包装，传入原消息链，不在此处合成。例如目标为 `Haqi8mi:GroupMessage:824067832` 时，使用 Haqi8mi 机器人下 824067832 群的开关、字数、概率和音色。即使任务运行中修改了目标设置，也以发送时读取到的配置为准；未初始化的目标仍默认关闭。

支持完整 UMO 字符串和 `MessageSession`，WebChat 保留完整用户会话标识。OneBot、Slack、QQ 官方及飞书的群成员隔离会话按适配器规则还原到收件群，再读取该群设置；不会修改传给平台的原始路由参数。新版 `AgentWakeupEvent` 同样按目标解析，最终响应钩子不提前抽取概率或合成，实际发送时处理一次。

原生 `send_message_to_user`、`StarTools.send_message` 和 `AgentWakeupEvent.send` 都覆盖。用“当前 asyncio 任务＋实际目的地”关联一次嵌套发送，避免 `event.send → Context → adapter` 重复转换或重复抽取概率；子任务即使继承了 ContextVar，也因任务身份不同而独立处理。这不是去重键，同一任务向同一目的地明确发送两次，仍处理两次。模型或工具在流生成过程中主动发送也独立处理，不继承外层流的发送作用域。

已有语音和工具状态、推理等控制消息跳过；`/usetts` 自身回执保持文字。发送异常继续由原调用方处理，不额外重发。直接调用平台 SDK、绕过上述事件及适配器接口的插件不在覆盖范围内。这里处理每次明确发送的正文，无法从第三方插件已发送的多条消息中判断哪条才是其最终结论。

## GSVI 协议与认证

仅使用 `GET /models/{version}`、`POST /infer_single` 和返回的 `audio_url`，不使用 OpenAI 或 `/api/voices` 接口。合成请求采用 GSVI 字段 `version`、`model_name`、`text`、`text_lang`、`emotion`、`dl_url`、`media_type: wav`；参考语言非空时增加 `prompt_text_lang`。

配套 gpt-sovits-next 服务的 `v4` 是兼容命名空间，可以访问所有已注册音色，不代表实际权重为 v4。

- `api_key`：非空时生成 `Authorization: Bearer <key>`。
- `request_headers`：JSON 字符串，例如 `{"X-API-Key":"your-key"}`。Header 名称不区分大小写，自定义 Authorization 优先于自动生成值。
- `download_headers`：可选，音频下载专用的 JSON Header。覆盖同名服务 Header。
- 同源下载沿用服务认证；异源下载只使用显式下载 Header。重定向时重新判断来源，不向其他源自动转发这些凭据。
- 合成 POST 的 Content-Type 固定为 application/json；其他 Header 可自定义。
- Key 与 Header 字段在配置面板中遮罩，指令状态和错误日志不回显密钥或服务器响应正文。

插件只发送认证信息，服务端或反向代理必须负责校验。配套 gpt-sovits-next 服务当前没有 API Key 校验，填写 Key 不会自动启用服务端访问控制。

## 验证

在 v4.28.0、v4.29.4 和核查时的 master 源码上各通过 80 项回归（合计 240 项），覆盖命令、原生指令过滤器、真实本地 HTTP 服务、渠道隔离、认证下载、错误回退、重查询、中间过滤、主 Agent 先确认与后台后回传、图文透传、动态配置，以及发送作用域、模型响应与流式选项不变、流式语音清理、普通媒体发送、新适配器绑定和卸载恢复。来源筛选单独覆盖未知插件发送、普通命令、同任务插件通知、跨任务共享 event、嵌套请求不覆盖主任务来源、cron/后台 Agent 唤醒、流生成期间的非模型发送及插件自行流式回执。KV 使用内存替身，没有新增数据库测试。

另用上游真实 fallback、工具执行、`send_message_to_user`、`Context.send_message` 和 `RespondStage.process` 做 18 组对照：原生、仅最终回复、仅 TTS、两个插件同时使用，非流式和流式的模型调用顺序、工具调用次数、原始模型历史及实际消息数量都与各自原生基线一致。包含 A==B/A!=B、主模型失败切换和不发生切换的对照。

直接调用正在运行的 GSVI 服务验证了音色校验、合成、下载及发送层音频处理。ZIP 通过上游实际元数据校验和解压流程，源码通过 Ruff 检查。模型与聊天适配器使用替身，尚未连接真实 QQ 等聊天平台做端到端发送测试。
