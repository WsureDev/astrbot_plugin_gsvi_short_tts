# astrbot_plugin_gsvi_short_tts

直接调用 GSVI HTTP 服务的 AstrBot 短文本 TTS 插件。群聊、私聊和 WebChat 各自设置音色、字数界限、触发概率，默认关闭。

## 安装与设置

在 AstrBot 插件页面通过仓库地址 `https://github.com/WsureDev/astrbot_plugin_gsvi_short_tts` 安装，也可以上传 ZIP，或将本目录放入 `AstrBot/data/plugins/astrbot_plugin_gsvi_short_tts/` 并重载。支持 AstrBot `>=4.28,<4.30`，复用其 aiohttp、Pydantic 等已有依赖。

在插件配置中填写 AstrBot 能访问的 GSVI 服务地址，并设置全局初始化预设。默认预设为“花火、100 字、100%”，但所有新渠道仍为关闭状态。

完全不依赖 AstrBot TTS Provider，不需要启用其语音合成开关。当前只处理内置工具循环 Agent 的最终响应，插件或工具自行主动发送的消息不处理；Live Mode 不在支持范围内。

本插件的开关和概率只管理本插件。若同时启用了 AstrBot 原生 TTS 或其他语音插件，它们仍有各自的触发规则；需要由本插件独立控制语音时，请关闭那些额外的自动转换。

## 音色下拉与刷新

1. 填写服务地址、版本和认证信息，保存配置。
2. 插件在后台请求 `/models/{version}`，稍后重新打开配置即可在“预设音色”中下拉选择。
3. 需要再次拉取时，勾选“刷新音色列表（执行一次）”并保存；开关自动复位，重新打开配置查看结果。

加载、重载和保存配置后会自动刷新，无需每次勾选。刷新不阻塞插件加载，最多等待 10 秒（配置的请求超时更短时使用更短值）。列表只更新运行时 Schema，插件目录中的 `_conf_schema.json` 不会被改写。

最近一次成功列表按服务地址和版本缓存在插件 KV 中。刷新失败时保留已有列表和当前选择，在音色字段提示中显示原因；首次加载失败且没有缓存时保留手动输入。服务端已移除的当前音色仍保留，并标注“当前选择，服务列表未列出”，不会自动改选其他音色。

此下拉框设置的是全局初始化预设。已通过 `/usetts` 保存的渠道音色继续独立生效，不随预设变化。

## 指令

| 指令 | 行为 |
| --- | --- |
| `/usetts 花火 80 50` | 当前渠道设置为花火、最多 80 字、50% 概率，并开启 |
| `/usetts on` | 已有配置则开启；没有配置则复制全局预设后开启 |
| `/usetts off` | 保留参数并关闭；没有配置则复制全局预设并保存为关闭 |
| `/usetts` | 查看状态、音色、字数、概率和配置来源，不写入设置 |
| `/usetts list` | 实时查询 GSVI 并列出当前版本全部音色，不改变渠道配置 |

字数必须为正整数，概率必须为 0–100 的整数。音色使用 `/models/{version}` 返回的角色键；包含空格时使用引号，例如 `/usetts "某个 角色" 80 50`。初始化时检查角色和情绪是否存在，错误不会覆盖现有配置。关闭已有配置不要求服务在线。

`/usetts list` 无需先开启或初始化渠道，始终查询服务端当前列表；查询失败时返回原因，不把旧缓存当作实时可用音色。列表回执为文字，不触发 LLM 或 TTS。

每个机器人实例下，每个群共用一份设置、每个私聊对象一份设置、每个 WebChat 用户会话一份设置。群设置不受 LLM 按群成员隔离会话的影响。设置复用 AstrBot 插件 KV 存储，重启保留；不同渠道独立写入。多实例需要共用 AstrBot 的持久化后端才能共享渠道设置，插件没有额外的全局配置缓存。

## 触发与发送

只对最终响应中所有文字组件按顺序拼接的完整正文判断一次：去除首尾空白后按 Unicode 码点计数，中文、英文字母、标点和内部空白均计入。长度小于或等于界限且命中概率时生成一条 WAV 语音；0% 永不合成，100% 在长度满足时必定尝试。

成功后以语音替换文字，保留图片、提及等其他组件及消息链元数据。模型上下文保留原始文字。已有语音、空文字、超长、未命中、HTTP 错误或合成失败均保留原回复，不截断文字。

为确保最终响应钩子在发送前运行，对启用且概率大于 0 的渠道关闭本轮流式输出，并对该请求使用可恢复的 `ToolLoopAgentRunner.step()` 包装，丢弃中间文本和工具状态，等最终响应钩子完成后发送。这样也覆盖 skills_like 重查询提前产出文本的分支。未启用渠道及 0% 渠道保持原输出行为。

该运行时包装不修改 AstrBot 源码，停用时恢复；与 `astrbot_plugin_llm_result_final_only` 可同时使用，不依赖其安装。其他包装相同方法的插件仍需一起验证。临时音频交给 AstrBot 的事件生命周期清理，WebChat 会在清理前复制到附件目录。

## GSVI 协议与认证

仅使用 `GET /models/{version}`、`POST /infer_single` 和返回的 `audio_url`，不使用 OpenAI 或 `/api/voices` 接口。合成请求采用 GSVI 字段 `version`、`model_name`、`text`、`text_lang`、`emotion`、`dl_url`、`media_type: wav`；参考语言非空时增加 `prompt_text_lang`。

配套 gpt-sovits-next 服务的 `v4` 是兼容命名空间，可以访问所有已注册音色，不代表实际权重为 v4。

- `api_key`：非空时生成 `Authorization: Bearer <key>`。
- `request_headers`：JSON 字符串，例如 `{"X-API-Key":"your-key"}`。Header 名称不区分大小写，自定义 Authorization 优先于自动生成值。
- `download_headers`：可选，音频下载专用的 JSON Header。覆盖同名服务 Header。
- 同源下载沿用服务认证；异源下载只使用显式下载 Header。重定向时重新判断来源，不向其他源自动转发这些凭据。
- 合成 POST 的 Content-Type 固定为 application/json；其他 Header 可自定义。
- Key 与 Header 字段在配置面板中遮罩，指令状态和错误日志不回显密钥或服务器响应正文。

插件只发送认证信息，服务端或反向代理必须负责校验。配套 gpt-sovits-next 服务当前没有 API Key 校验，填写 Key 不会自动启用服务端访问控制。

## 验证

在 v4.28.0、v4.29.4 和核查时的 master 源码上各通过 37 项回归（合计 111 项），包含音色列表指令、原生指令过滤器、真实本地 HTTP 服务、分渠道设置、认证下载、错误回退、重查询、两个插件的加载顺序，以及原生配置 API 返回动态下拉选项、刷新复位、缓存恢复、失败保留和后台任务取消。KV 使用内存替身，没有新增数据库测试。

另直接调用正在运行的 GSVI 服务，用“花火”合成一段 2.88 秒、32000 Hz 的 WAV，验证了音色校验、合成、下载、语音组件替换与临时文件注册。ZIP 通过上游实际元数据校验和解压流程，源码通过 Ruff 检查。尚未连接真实 QQ 等聊天适配器做端到端发送测试。
